# planning/specs -- feature specs

One job: WHAT to build and WHY (not HOW). Implementation follows the backend/frontend
conventions and folder CONTEXTs.

## What's here
- `backend-spec.md` -- the FastAPI service scope.
- `frontend-spec.md` -- the Next.js app scope.

## Rules
- A spec states: problem, proposal, scope (in/out), dependencies, open questions.
- Keep HOW out of specs -- that lives in code + the folder CONTEXTs.

## Where to add things
- A new feature -> a `kebab-case-spec.md` here before building it.
